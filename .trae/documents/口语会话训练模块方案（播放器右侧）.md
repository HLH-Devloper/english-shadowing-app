# 目标与范围
- 在播放器右侧新增“口语会话”选项卡(Tab)，与“字幕列表”并列。
- 以会话式交互帮助用户针对当前选中的字幕进行英文复述与练习，获得人工智能(AI)教师评分与建议。
- 保留每句字幕的练习历史记录，支持多次尝试。

# 架构与集成位置
## 现有页面与组件
- 播放器页面：`src/components/PlayerPage.jsx`（含右侧面板、字幕列表、句子点击逻辑、播放控制）。
- 右侧面板容器类：`.right-panel`（样式在 `src/index.css`、移动端适配在 `src/mobile.css`）。
- 字幕点击逻辑：`handleSubtitleClick(subtitle)`（更新当前活动下标并跳转时间）。

## 新增与改动点
1. 在 `PlayerPage.jsx` 的右侧面板顶部增加选项卡(Tab)导航：`字幕列表` / `口语会话`。
2. 新增“口语会话”选项卡内容组件：`SpeakingChatPanel`（建议新文件，复用既有样式体系）。
3. 引入跨选项卡可共享状态：`currentSentence`（英文原文与中文翻译，来源于字幕点击），以及每句的会话记录 `chatSessionsBySentenceId`。

# 用户界面(UI)设计
## 顶部（“口语会话”选项卡内部）
- 显示当前句的英文原文与中文翻译；若未选择则提示“请在字幕列表中选择一句话”。
- 提供“清空本句会话记录”“返回字幕列表”两个轻量操作按钮。

## 中部聊天区
- 对话泡泡样式：圆角、柔和阴影、现代配色，支持深色模式。
- 进入时展示固定开场白（系统泡泡）：
  - 「用你自己的话，用英文说一遍这句话的意思。不用逐字一样，只要意思差不多就行。」
- 加载中状态：教师回复的骨架屏与旋转细微指示，避免跳动。
- 消息结构：`role: 'system' | 'user' | 'assistant'`，`content` 文本；教师回复包含评分与建议的结构化呈现：
  - 词汇多样性、语法准确度、语义贴合度、流利度子项；
  - 总分与一句话总结；
  - 更自然的改写建议（给出 1～2 种）；

## 底部输入区
- 单行输入框与“发送”按钮；支持按 Enter 发送、Shift+Enter 换行。
- 预留“从录音识别结果填入”的入口（后续集成语音识别时复用同一发送流程）。

## 现代风格细节
- 玻璃拟态（轻微背景模糊）、微动效（悬浮、发送气泡渐入）。
- 自适应与响应式：在窄屏或移动端抽屉模式下，聊天区高度自适应并保持良好滚动体验。

# 交互与状态流
1. 用户点击字幕列表某一句：
   - 仍然高亮（现有逻辑保留）。
   - 将该句赋值为 `currentSentence = { id, original, translation }`。
2. 用户切换到“口语会话”选项卡：
   - 顶部显示 `currentSentence.original` 与 `currentSentence.translation`。
   - 中部聊天区载入该句的历史消息列表（若首次则仅有固定开场白）。
3. 用户在底部输入框填写英文并发送：
   - 立即以“我”的气泡显示本次内容。
   - 触发后端评估接口请求，拿到评分与建议后，追加“老师回复”的气泡。
4. 历史保留：
   - 每个句子维护独立的消息列表（键为 `sentenceId`）。
   - 支持清空本句记录（不影响其他句）。

  - 提供暗色模式变量与浅色模式兼容。

# 后端接口设计（调用 Gemini）
- 新增服务端应用程序编程接口(API)：`POST /api/speaking-eval`
  - 请求体：`{ sentenceId, original, translation, userText, userId? }`
  - 行为：构造提示词，调用 Gemini 评估用户复述；返回结构化结果。
- 环境变量：
  - `GEMINI_API_KEY`（仅服务端使用，不暴露到前端）。
- 返回示例：
  ```json
  {
    "score": 4.2,
    "rubric": { "fluency": 4.0, "accuracy": 4.5, "vocabulary": 4.0, "grammar": 4.0 },
    "summary": "整体表达清晰，语义贴合度较好。",
    "correction": "...（更自然的改写）...",
    "suggestions": ["...", "..."],
    "refs": { "original": "...", "translation": "..." }
  }
  ```
- 安全与容错：
  - 服务端校验与清洗输入；节流或速率限制以防滥用。
  - 本地开发不可用时，前端友好报错并保留消息记录（不改变线上逻辑）。

# 数据持久化策略
- 未登录用户：本地 `localStorage` 以 `videoId + sentenceId` 为键存储会话记录。
- 已登录用户（已接入 Firebase）：将会话记录同步到 Cloud Firestore 的用户文档下（轻量字段，分页或截断防过大）。
- 同步策略：前端先乐观更新，后台成功后补写；失败则保持本地副本并提示。

# 无障碍与可用性
- 键盘操作：Enter 发送、Shift+Enter 换行；Tab 导航输入与按钮；屏幕阅读器ARIA标签。
- 滚动管理：发送或接收后自动滚动到底部；长消息折叠展开。

# 性能与兼容
- 状态隔离每句独立列表，避免大规模渲染；必要时对聊天区进行虚拟化。
- 移动端抽屉模式中保持右侧面板的良好可用性；横屏低高度时隐藏策略遵循现有媒体查询。
